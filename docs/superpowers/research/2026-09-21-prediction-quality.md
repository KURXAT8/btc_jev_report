# Jev 預測品質研究計畫

狀態：2026-09-23 使用者授權實作本機持續校準；`calibration.py`／`learning.py` 已依新的[持續校準設計](../specs/2026-09-23-continuous-calibration-design.md)實作。下文保留最初研究規劃；涉及自動校準與採用的部分以新設計為準。同日期新聞對照等額外 API 研究仍未啟用，預算為零。

前置文件：[設計規格](../specs/2026-09-21-btc-jev-daily-email-design.md)、[實作計畫](../plans/2026-09-21-btc-jev-daily-weekly-email.md)。日報顯示正式版本，研究結果在週報的獨立區塊呈現。

## 1. 研究目的與邊界

衡量新資料、新提問或機率校準，是否在未參與調整的未來樣本上優於現行版本。改進判定包括機率品質、分類表現、涵蓋率、穩定性與成本，不只挑最高命中率。

AI 仍只用 Jev。統計評分及日後機率校準由本機程式計算，不加入其他 AI API，也不宣稱可以微調 Jev 模型權重。

## 2. 同日期對照實驗

一次只開一個候選版本，固定 model、標籤門檻、資料截止時間與基準價格；先選一項變更，例如「第二階段含新聞／不含新聞」。共用已保存的新聞分類和市場資料，兩個版本均須在當天報告凍結前完成。

每個實驗啟用前記錄：

- `experiment_id`、假設、唯一變更項、正式／候選規則版本與來源快照。
- 固定起訖日期、主要衡量指標（預設各時間尺度的 paired Brier 差）、次要指標和評估方法。
- 額外請求／輸入量／帳戶費用預算、截止時間與失敗處理。
- 樣本不足時的延期規則；不得看過結果後反覆改終點找出漂亮數字。

第一個候選方案上限為每日額外一次趨勢邏輯請求、最多三次 HTTP 嘗試、每次 24 KiB；正式流程仍保留每日九次上限，兩邊分開記帳。研究預設額度為零，啟用時才設定預算；日報優先，研究逾時不延誤日報。

配對鍵為 `(as_of, horizon_days, reference_price, label_version)`。同時報告兩版各自的成功／失敗數，以及成功配對集合的比較；候選失敗日不能無聲消失。未到期資料不評分、歷史重跑不冒充即時預測。

## 3. 時間順序驗證與重疊樣本

提問、校準或門檻的調整只使用較早資料；在較後、未參與調整的區段驗證。訓練／校準候選樣本的 `due_at` 及實際 `settled_at` 都必須早於驗證起點。

3 天與 7 天標籤有重疊視窗，不用隨機切分製造獨立樣本的假象。共用時間切分時，採至少 7 天的邊界隔離，並排除所有跨越邊界或尚未取得結果的樣本。區間估計使用保留時間相依性的區塊方法；區塊長度不得短於最長 7 天，還需檢查更長相依性。

研究窗口須涵蓋多種行情並檢查每類樣本數。30 筆是第一版顯示小樣本提醒的門檻，不是足以擬合校準器、通過顯著性檢定或採用新版本的證明。

## 4. 機率可靠度與校準

第一版先觀察：對每個方向分別將原始機率分成五個固定區間，顯示樣本數、平均模型機率和實際發生率。這是描述性可靠度表，低樣本不得用來做確定結論；Brier score 同時受區分能力等因素影響，不能單獨當校準證明。

日後才評估校準器：

1. 保存原始三類機率、模型與規則版本，永不覆寫。
2. 先試單一溫度參數：`q_k = exp(log(max(p_k, ε))/T) / Σ_j exp(log(max(p_j, ε))/T)`，固定 `ε=1e-6` 並保存轉換版本；`T` 只在過去校準區間擬合。
3. 在更晚的獨立區間比較原始／校準機率的 Brier、log loss、可靠度表與涵蓋率。
4. 報告樣本量、類別覆蓋、日期與重疊樣本限制。沒有證據支持就維持原始版本，不部署自動再訓練。

若採用校準版本，郵件區分「Jev 原始機率」與「本機校準機率」；校準後機率不能再稱為 Jev confidence。既有歷史郵件保持原貌。

## 5. 市場情境與保留判斷

第一版依預測當時固定的趨勢／波動標籤分組觀察。後續可測試特定情境下的保留判斷政策，但須同時報告涵蓋率與全部預測成效，不能只保留答對的場景。

同一個 Jev 多次回答不代表多個獨立專家。任何候選政策的採用都要對照實驗；不以多數決或短期單週命中率直接升級。

## 6. 採用、停止與回復

評估完成後保留完整結果，包括無改善和負面結果。新版本須在預先指定指標上顯示可信改善，且失敗率、樣本涵蓋和成本沒有不可接受的退步，才提出版本切換。

切換保存新的版本與起始日，保留舊版本可回復。異常或效能退化先停用候選／校準，不自動加大預算或更換模型。研究未啟用時，所有研究命令都必須保持零額外模型請求。

## 7. 未來研究模組與驗收

規劃模組為 `experiments.py`、`calibration.py`，測試為 `test_experiments.py`、`test_calibration.py`；開始研究開發前另寫逐項實作計畫，第一版不建立空殼程式。

必要驗收包括：零預算不發請求、配對鍵不混淆版本、候選失敗仍被計數、時間切分無未到期標籤洩漏、溫度轉換三類總和為一、原始機率不變、週報標示樣本範圍，以及停用研究不影響日報。

參考：[時間序列交叉驗證](https://otexts.com/fpp3/tscv.html)、[機率校準與可靠度](https://scikit-learn.org/stable/modules/calibration.html)、[TypeSafe 設計指南](https://docs.typesafe.ai/concepts/how-to-build-with-system-one)。這些方法支持評估設計，不是 Jev 對 BTC 有預測優勢的證據。
